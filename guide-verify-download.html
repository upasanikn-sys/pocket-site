Check your download is the real one

Category
Security
By
Pocket
Reviewed
4 Nov 2026
Read
4 min
In short: every file on the Download page is listed with its SHA-256, a 64-character fingerprint of the file's exact bytes. Windows, macOS and Linux each have a built-in command that prints the fingerprint of a file. When it is the page's, the file is the one that was published, byte for byte; change one byte and the fingerprint is a different one.

What the number is

A SHA-256 is worked out from every byte of a file and is always 64 digits (0 to 9 and a to f).

It cannot be read back into the file. A download that stopped part-way, a file edited after it was published and a file of another version each print a different one. The Download page lists one for each file, taken from the record of what was published, version 3.2.11 of 26 October 2026.

On Windows, in PowerShell

  1. Open PowerShell in the folder the file was saved to, usually Downloads.
  2. The command below prints the file's SHA-256 in the Hash column. PowerShell writes the digits in capitals and the page in small letters; they are the same digits. 
    Get-FileHash .\Pocket_3.2.11_windows_setup.exe -Algorithm SHA256
    For the published installer it prints a table like this, the path being the file's own: 
    Algorithm       Hash                                                                   Path
---------       ----                                                                   ----
SHA256          0CB574461375D1A18C18D693C1EF47CF539B1C16185D69B8C3EB9EEA59574CDD       C:\Users\you\Downloads\Pocket_3.2.11_windows_setup.exe
  3. To have PowerShell compare, the same command with the page's hash after -eq prints True or False. 
    (Get-FileHash .\Pocket_3.2.11_windows_setup.exe -Algorithm SHA256).Hash -eq "0cb574461375d1a18c18d693c1ef47cf539b1c16185d69b8c3eb9eea59574cdd"

On a Mac, in Terminal

  1. Open Terminal and go to the folder the file was saved to, usually Downloads.
  2. The command below prints the file's SHA-256, then its name. 
    shasum -a 256 Pocket_3.2.11_macos.dmg
  3. Passing the page's hash and the file's name, two spaces apart, to shasum -a 256 -c has the Mac compare them: it prints the name with OK, or FAILED. 
    echo "cb40506822c63644d0fb678e24a3a407af7e0bf0ab25cbed886312df35f2741a  Pocket_3.2.11_macos.dmg" | shasum -a 256 -c

On Linux, in a terminal

  1. Open a terminal in the folder the file was saved to.
  2. The command below prints the file's SHA-256, then its name. sha256sum, which comes with most distributions, prints the same. 
    shasum -a 256 Pocket_3.2.11_linux_amd64.deb
  3. Passing the page's hash and the file's name, two spaces apart, to shasum -a 256 -c has it compare them: it prints the name with OK, or FAILED. 
    echo "91aca36dbaa72df99bb99a3ec4e004c45bc28d642704cdfa41c7b8e901106b1a  Pocket_3.2.11_linux_amd64.deb" | shasum -a 256 -c

What a match shows, and what it does not

A match shows the file on your computer is the one published: it was not cut short and nothing changed it on the way.

It does not show who made it. Pocket's builds are not signed yet, which is why Windows and macOS warn at the first open; a fingerprint listed beside the file shows the file is unchanged, not who published it. A fingerprint that differs shows the file is not the one published. Earlier releases' hashes are kept in the shipping record.

Questions

What is a SHA-256?

A 64-digit fingerprint worked out from every byte of a file. The same file always gives the same one, and any change to the file gives a different one.

The hash PowerShell prints is in capitals and the page's is not. Is that a match?

Yes. Hexadecimal digits are the same in capitals or small letters; PowerShell prints capitals, shasum small letters.

Does a match mean Pocket is signed?

No. Pocket's builds are not signed yet, which is why Windows and macOS warn at the first open. A match shows the file is the one published on the page it came from.

Where are the hashes of earlier releases?

In the shipping record, each version with its date, files and SHA-256.
